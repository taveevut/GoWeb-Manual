1. ภาพรวมระบบและสถาปัตยกรรม (System Overview)

ระบบบริหารจัดการเว็บไซต์ (Web Content Management System) ถูกพัฒนาขึ้นเพื่อตอบสนองการดำเนินงานขององค์กรภาครัฐ รัฐวิสาหกิจ และองค์กรปกครองส่วนท้องถิ่น (อปท.) โดยมีจุดเด่นดังนี้:

  • การตอบสนองแบบเรียลไทม์ (Reactive UI): พัฒนาบนพื้นฐานของ Laravel และ Livewire ทำให้การสลับหน้า บันทึกข้อมูล กรองข้อมูล และแบ่งหน้าทำงานได้อย่างรวดเร็วโดยไม่ต้องรีโหลดทั้งหน้าเว็บ
  • มาตรฐานการออกแบบ UI ที่เป็นเอกภาพ (Unified Design System): ทุกหน้าจอรายการและฟอร์มถูกสร้างขึ้นบนโครงสร้างเดียวกัน (CRUD Pattern) ทำให้เจ้าหน้าที่สามารถเรียนรู้การใช้งานเมนูใหม่ได้ทันทีโดยไม่ต้องอบรมซ้ำ
  • ระบบความปลอดภัยตามมาตรฐานสากล: รองรับการยืนยันตัวตนสองชั้น (2FA/reCAPTCHA), สิทธิ์การเข้าถึงตามบทบาท (Role-Based Access Control - RBAC), การเข้ารหัสรหัสผ่าน และการบันทึก Audit Log ทุกกิจกรรมสำคัญ
  • รองรับการเชื่อมต่อข้อมูลภาครัฐ: มีโมดูลรองรับระบบจัดซื้อจัดจ้างภาครัฐ (e-GP), หนังสือราชการอิเล็กทรอนิกส์, การประเมิน ITA และเกณฑ์มาตรฐาน LPA

2. การเข้าสู่ระบบและการจัดการบัญชีผู้ใช้ (Authentication & Account)

2.1 ขั้นตอนการเข้าสู่ระบบ (Sign In)

  • URL เข้าสู่ระบบ: https://[ชื่อโดเมนของหน่วยงาน]/auth (หรือ http://127.0.0.1:8000/auth ในสภาพแวดล้อมทดสอบ)

ขั้นตอนการปฏิบัติ:

  1. เปิดเว็บบราวเซอร์ (แนะนำ Google Chrome, Microsoft Edge หรือ Safari เวอร์ชันล่าสุด)
  2. ไปที่ URL สำหรับเข้าสู่ระบบหลังบ้านของหน่วยงาน
  3. กรอก ชื่อผู้ใช้งาน (Username) ที่ได้รับมอบหมายจากผู้ดูแลระบบ
  4. กรอก รหัสผ่าน (Password)
  5. (ทางเลือก) ติ๊กเครื่องหมายถูกที่ช่อง "จำฉันไว้ในระบบ" หากใช้งานบนเครื่องคอมพิวเตอร์ส่วนตัวในการปฏิบัติงาน
  6. ติ๊กยืนยันการตรวจสอบความปลอดภัย "I'm not a robot" (Google reCAPTCHA) เพื่อป้องกันการเข้าถึงจากโปรแกรมอัตโนมัติ
  7. คลิกปุ่ม "เข้าสู่ระบบ" เพื่อเข้าสู่ระบบหลังบ้าน

2.2 การจัดการบัญชีผู้ใช้และการเปลี่ยนรหัสผ่าน

ผู้ใช้งานสามารถคลิกที่ปุ่มโปรไฟล์ชื่อของตนเองบริเวณมุมบนขวา เพื่อเข้าสู่เมนูส่วนตัว:

ข้อมูลบัญชีส่วนตัว (/auth/account) เปลี่ยนรหัสผ่านความปลอดภัย (/auth/password)
  • ข้อมูลบัญชี (/auth/account): ตรวจสอบข้อมูลชื่อ-นามสกุล, อีเมลสำหรับติดต่อ และชื่อบัญชี
  • เปลี่ยนรหัสผ่าน (/auth/password): เปลี่ยนรหัสผ่านใหม่เพื่อความปลอดภัย โดยต้องระบุรหัสผ่านเดิม และรหัสผ่านใหม่ที่มีความยาวอย่างน้อย 8 ตัวอักษร
  • การออกจากระบบ (Logout): คลิกที่เมนูชื่อบัญชีมุมบนขวา แล้วเลือก "ออกจากระบบ" ระบบจะทำลาย Session ในบราวเซอร์เพื่อป้องกันผู้อื่นเข้าใช้งานต่อ

3. ภาพรวมแดชบอร์ดหลัก (Dashboard Overview)

  • URL: /auth/dashboard

แดชบอร์ดเป็นศูนย์รวมข้อมูลสรุปและสถานะการดำเนินงานของเว็บไซต์แบบเรียลไทม์ ประกอบด้วย:

  1. แถบต้อนรับและสถิติรวม (Header Stats):
    • แสดงชื่อผู้ปฏิบัติงานที่กำลังล็อกอิน
    • แสดงตัวเลข "เนื้อหาทั้งหมด" ที่มีอยู่ในระบบ
    • แสดงตัวเลข "คำร้อง / ความคิดเห็น" ที่รอดำเนินการตอบกลับ
    • ปุ่มเปิดดูหน้าเว็บไซต์สาธารณะ (เปิดแท็บใหม่)
  2. สวิตช์โหมดแสดงผลพิเศษ (Display Mode):
    • โหมดไว้อาลัย (Mourning Mode): สวิตช์เปิด/ปิดโทนสีและการแสดงริบบิ้นไว้อาลัยบนหน้าเว็บไซต์สาธารณะในวาระสำคัญ
  3. การ์ดสรุปจำนวนเนื้อหาเว็บไซต์:
    • รายงานจำนวน ข่าวสาร, ภาพสไลด์แบนเนอร์, ภาพกิจกรรม, หน้าเพจ, แหล่งท่องเที่ยว และสินค้าชุมชน
  4. การ์ดบริการประชาชน (E-Service Summary):
    • แสดงสถานะคำร้องที่ส่งเข้ามาจำแนกตามประเภทงาน เช่น แจ้งเหตุ, ขอซ่อมไฟฟ้า, เบี้ยผู้สูงอายุ, จดทะเบียนพาณิชย์ และข้อคิดเห็น
  5. รายการข่าวสารล่าสุด: รายการข่าว 5 ลำดับล่าสุด พร้อมระบุสถานะ (เผยแพร่ / ฉบับร่าง)
  6. ปุ่มทางลัดด่วน (Quick Navigation): เข้าสู่หน้าการทำงานหลักได้ในคลิกเดียว เช่น เพิ่มข่าว, จัดการภาพสไลด์, ตั้งค่าหน่วยงาน, จัดการเมนู และจัดการผู้ใช้งาน

4. มาตรฐานการจัดการข้อมูลแบบ CRUD (Standard CRUD Operations)

ระบบใช้สถาปัตยกรรม Unified CRUD Blueprint ที่เป็นมาตรฐานเดียวกันในทุกโมดูล ทำให้ผู้ใช้งานสามารถเข้าใจขั้นตอนการทำงานได้อย่างรวดเร็ว

4.1 [R - Read] การเปิดดูรายการ การค้นหา และตัวกรอง

  • ค้นหาด่วน (Search Bar): พิมพ์คำค้นหา (เช่น ชื่อเรื่อง, หัวข้อ, หรือข้อความสำคัญ) ระบบจะค้นหาและแสดงผลทันทีโดยไม่ต้องกด Enter
  • ตัวกรองหมวดหมู่ (Category Filter): เลือกหมวดหมู่ที่ต้องการจากเมนูดรอปดาวน์เพื่อจำแนกประเภทข้อมูล
  • การจัดเรียงลำดับ (Column Sorting): คลิกที่หัวตาราง (เช่น หัวข้อ, วันที่ลงประกาศ, วันที่สร้าง) เพื่อสลับการเรียงลำดับจากล่าสุดไปเก่าสุด หรือจากน้อยไปมาก
  • การแบ่งหน้า (Pagination & Page Size): สามารถเลือกจำนวนข้อมูลที่แสดงต่อหน้าได้ (15, 25, 50 รายการ) ที่มุมล่างขวา

4.2 [C - Create] การเพิ่มข้อมูลใหม่

  1. คลิกปุ่ม "+ เพิ่ม..." (เช่น + เพิ่มข่าว, + เพิ่มรายการ, + เพิ่มกิจกรรม) ที่แถบเมนูด้านบน
  2. ระบบจะเปิดหน้าต่าง Modal Dialog ขึ้นมา โดยแบ่งส่วนการกรอกข้อมูลเป็นหมวดหมู่อย่างเป็นระเบียบ:
    • ข้อมูลพื้นฐาน: ระบุหัวข้อหลัก, หมวดหมู่, กำหนดสถานะ (ฉบับร่าง หรือ เผยแพร่), และบทคัดย่อ
    • การเผยแพร่: กำหนดวันที่ลงประกาศ, วันที่เริ่มแสดงผล, วันที่สิ้นสุด (ตั้งเวลาปลดอัตโนมัติ), และลิงก์อ้างอิงภายนอก
    • สื่อและรูปประกอบ: อัปโหลดรูปภาพหน้าปก (Cover Image) และไฟล์เอกสารแนบ (PDF, Word, Excel)
    • เนื้อหาละเอียด: พิมพ์และจัดหน้าเนื้อหาด้วยเครื่องมือ Rich Text Editor (CKEditor)
  3. คลิกปุ่ม "บันทึก" (สีเขียว) มุมล่างขวาเพื่อบันทึกข้อมูลเข้าสู่ระบบทันที

4.3 [U - Update] การแก้ไขข้อมูลและตัวเลือกประจำแถว

  1. ในตารางรายการ ให้เลื่อนไปยังแถวข้อมูลที่ต้องการปรับปรุง
  2. คลิกปุ่ม จุด 3 จุด (⋮) ที่คอลัมน์เมนูด้านซ้าย จะปรากฏตัวเลือก:
    • แก้ไข: เปิดหน้าต่างฟอร์ม Modal Dialog เพื่อแก้ไขข้อมูลเดิม
    • ดูหน้าบ้าน / ดูตัวอย่าง: เปิดแท็บใหม่เพื่อดูการแสดงผลจริงบนหน้าเว็บไซต์สาธารณะ
    • ลบ: ดำเนินการลบรายการนั้นๆ ออกจากระบบ

4.4 [D - Delete] การลบข้อมูลเดี่ยว และการลบแบบกลุ่ม (Bulk Actions)

การยืนยันความปลอดภัยก่อนลบข้อมูล การเลือกหลายรายการเพื่อจัดการพร้อมกัน (Bulk Actions)
  • การลบรายการเดี่ยว (Single Delete):
    • เมื่อคลิกปุ่ม "ลบ" ระบบจะมีหน้าต่างยืนยันความปลอดภัย (Confirm Dialog) แจ้งเตือนเพื่อป้องกันการลบข้อมูลโดยอุบัติเหตุ
    • เมื่อกดยืนยัน ระบบจะลบข้อมูลและไฟล์รูปภาพ/ไฟล์แนบที่ผูกอยู่กับรายการนั้นออกจาก Server ทันที
  • การจัดการหลายรายการพร้อมกัน (Bulk Actions):
    1. ติ๊กเครื่องหมายถูกที่ช่องสี่เหลี่ยมด้านหน้ารายการที่ต้องการจัดการ (หรือติ๊กช่องบนสุดของหัวตารางเพื่อเลือกทุกรายการในหน้านั้น)
    2. เมนู "ดำเนินการ (จำนวนที่เลือก)" ที่แถบเครื่องมือด้านบนจะพร้อมใช้งาน
    3. คลิกเพื่อเลือกคำสั่ง:
      • เผยแพร่: ปรับสถานะรายการที่เลือกให้แสดงบนหน้าเว็บพร้อมกัน
      • ฉบับร่าง: ปรับสถานะรายการที่เลือกให้ซ่อนจากหน้าเว็บพร้อมกัน
      • ลบที่เลือก (สีแดง): ลบรายการทั้งหมดที่เลือกพร้อมกันในครั้งเดียว

5. การบริหารจัดการเนื้อหาเว็บไซต์ (Content Management Modules)

5.1 ข่าวสารและประกาศ (News & Announcements)

  • จัดการข่าวสาร: /auth/news
  • จัดการประเภทข่าว: /auth/news/types
หน้ารายการข่าวสาร หน้าจัดการประเภทหมวดหมู่ข่าว
  • วัตถุประสงค์: เผยแพร่ข่าวประชาสัมพันธ์, ประกาศจัดซื้อจัดจ้าง, ประกาศรับสมัครงาน, และเอกสารข้อบัญญัติ/เทศบัญญัติ
  • แนวปฏิบัติ:
    1. แนะนำให้ตั้งค่าหมวดหมู่ข่าวที่หน้า "ประเภทข่าว" ให้ครบถ้วนก่อน
    2. ในหน้าข่าวสาร สามารถกำหนด "ปักหมุด" (Featured) เพื่อให้ข่าวนั้นคงอยู่ด้านบนสุดของหน้าแรกเสมอ
    3. ขนาดรูปภาพหน้าปกที่แนะนำ: สัดส่วน 4:3 (เช่น 800x600 พิกเซล)

5.2 ภาพสไลด์แบนเนอร์ประชาสัมพันธ์ (Banners)

  • URL: /auth/banners

  • วัตถุประสงค์: จัดการภาพแบนเนอร์สไลด์ขนาดใหญ่ด้านบนสุดของหน้าแรก เพื่อเน้นย้ำโครงการสำคัญหรือนโยบายหลัก
  • คุณสมบัติ:
    • รองรับทั้งแบนเนอร์สไลด์ขนาดเต็ม (L) และแบนเนอร์ขนาดย่อย (S)
    • กำหนดลำดับการเลื่อนแสดงผล (Sort Order)
    • กำหนดลิงก์ปลายทางเมื่อประชาชนคลิกที่ภาพแบนเนอร์ (ลิงก์ภายใน หรือเว็บไซต์ภายนอก)

5.3 ประมวลภาพกิจกรรม (Gallery)

  • URL: /auth/gallery

  • วัตถุประสงค์: เผยแพร่ภาพบรรยากาศการจัดกิจกรรม งานประเพณี การประชุม และการลงพื้นที่ของหน่วยงาน
  • การใช้งาน:
    • กำหนดชื่อกิจกรรม และวันที่จัดกิจกรรม
    • แนบรูปหน้าปกอัลบั้ม 1 ภาพ
    • อัปโหลดรูปภาพบรรยากาศในกิจกรรมได้ครั้งละหลายรูป (Multi-upload)

5.4 ปฏิทินกิจกรรมและนัดหมาย (Event Calendar)

  • URL: /auth/gallery/calendar

  • วัตถุประสงค์: ปฏิทินกลางสำหรับแสดงกำหนดการนัดหมาย วันประชุม งานเทศกาล และวันหยุดราชการ
  • มุมมอง: รองรับการแสดงผลแบบรายเดือน (Month), รายสัปดาห์ (Week), รายวัน (Day) และตารางรายการกำหนดการ (List View)

5.5 หน้าเพจเนื้อหาคงที่ (Static Pages)

  • URL: /auth/pages

  • วัตถุประสงค์: จัดการหน้าเนื้อหาหลักขององค์กร เช่น ประวัติความเป็นมา, วิสัยทัศน์/พันธกิจ, โครงสร้างส่วนราชการ, ยุทธศาสตร์การพัฒนา, อำนาจหน้าที่
  • การเชื่อมโยง: แต่ละหน้าเพจจะมี URL Slug เฉพาะ สามารถนำไปผูกเข้ากับระบบเมนูบนหรือเมนูข้างได้ทันที

5.6 ข้อมูลสถานที่และแหล่งท่องเที่ยว (Attractions & Landmarks)

  • URL: /auth/attractions

  • วัตถุประสงค์: ส่งเสริมสถานที่สำคัญ จุดแลนด์มาร์ก แหล่งท่องเที่ยวทางธรรมชาติ ประวัติศาสตร์ หรือศิลปวัฒนธรรมในพื้นที่
  • ข้อมูลในระบบ: ชื่อสถานที่, คำบรรยาย, แกลเลอรีภาพถ่าย, พิกัดแผนที่ (Google Maps Embed), และข้อมูลการติดต่อสอบถาม

5.7 สินค้าชุมชนและผลิตภัณฑ์ท้องถิ่น (OTOP & Local Products)

  • URL: /auth/otop

  • วัตถุประสงค์: ส่งเสริมและจัดแสดงผลิตภัณฑ์เด่นของกลุ่มแม่บ้าน วิสาหกิจชุมชน และสินค้า OTOP ในพื้นที่
  • ข้อมูลในระบบ: ชื่อสินค้า, รูปภาพผลิตภัณฑ์, รายละเอียดส่วนประกอบ, ราคาจำหน่าย, ชื่อกลุ่มผู้ผลิต และช่องทางการสั่งซื้อ

5.8 วิดีโอสื่อประชาสัมพันธ์ (Promotional Videos)

  • URL: /auth/promo-videos

  • วัตถุประสงค์: เผยแพร่วิดีทัศน์แนะนำองค์กร รายงานสรุปผลงาน หรือสารคดีชุมชน
  • การใช้งาน: นำลิงก์ URL หรือรหัส Embed จาก YouTube มาวาง ระบบจะดึงภาพปกและสร้างเครื่องเล่นวิดีโอบนหน้าเว็บให้อัตโนมัติ

5.9 กล่องข้อความและไฮไลต์หน้าแรก (Content Box)

  • URL: /auth/box

  • วัตถุประสงค์: จัดการพื้นที่พิเศษบนหน้าแรก เช่น สารจากผู้บริหาร, คำแถลงนโยบาย, ประกาศสำคัญเร่งด่วน หรือกล่องข้อความแนะนำบริการ

5.10 ระบบจัดการคลังสื่อและไฟล์อัปโหลด (Media & File Manager)

  • URL: /auth/editor-uploads

  • วัตถุประสงค์: ศูนย์รวมการจัดเก็บไฟล์ภาพ เอกสารแบบฟอร์ม PDF แผ่นพับ และสื่อดิจิทัลขององค์กร
  • ความสามารถหลัก:
    • สร้างโฟลเดอร์เพื่อจัดระเบียบไฟล์ตามหมวดหมู่
    • อัปโหลดไฟล์ด้วยการลากและวาง (Drag & Drop)
    • เปลี่ยนชื่อไฟล์ (Rename) และย้ายไฟล์ข้ามโฟลเดอร์ (Move)
    • คัดลอกลิงก์ไฟล์ไปใช้งานในบทความหรือเนื้อหาของระบบได้ทันที

5.11 การจัดการโครงสร้างเมนูเว็บไซต์ (Navigation Menus)

  • เมนูบน (Top Navbar): /auth/menu-top
  • เมนูข้าง (Sidebar Menu): /auth/menu-side
การจัดโครงสร้างเมนูบน การจัดโครงสร้างเมนูข้าง
  • วัตถุประสงค์: ออกแบบแผนผังการนำทาง (Site Navigation) ของเว็บไซต์
  • การใช้งาน:
    • เพิ่มเมนูหลัก และเมนูย่อยระดับ 2 (Sub-menu Dropdown)
    • กำหนดประเภทปลายทาง: ลิงก์ภายในระบบ (เลือกจากหน้าเพจหรือโมดูล) หรือ ลิงก์ภายนอก
    • จัดลำดับการแสดงผลเมนูได้โดยอิสระ

5.12 การตั้งค่าหน้าต้อนรับ ข้อมูลหน่วยงาน และ SEO (Site Settings)

  • หน้า Intro: /auth/setting/intro
  • ข้อมูลหน่วยงาน: /auth/setting/org
  • Meta SEO: /auth/setting/seo
หน้า Intro เทศกาลสำคัญ ข้อมูลหน่วยงานและช่องทางติดต่อ ตั้งค่า Meta SEO ค้นหา
  • หน้า Intro (/auth/setting/intro): เปิด/ปิดหน้าต้อนรับพิเศษ (Intro Gateway) ในวันสำคัญทางราชการ วันเฉลิมพระเกียรติ หรือเทศกาลประเพณี
  • ข้อมูลหน่วยงาน (/auth/setting/org): จัดการชื่อหน่วยงาน, ตราสัญลักษณ์ (Logo), ที่อยู่สำนักงาน, หมายเลขโทรศัพท์, อีเมลกลาง, แผนที่ Google Maps และลิงก์ Social Media (Facebook Page, LINE Official Account)
  • Meta SEO (/auth/setting/seo): กำหนด Title, Description, Keywords และภาพแชร์สำหรับโซเชียลมีเดีย (OpenGraph Image) เพื่อเพิ่มประสิทธิภาพการค้นหาบน Google

6. ระบบบริการประชาชนออนไลน์และการรับเรื่องร้องเรียน (E-Service & Public Engagement)

6.1 การจัดการคำร้องบริการออนไลน์ (E-Service Requests)

  • URL: /auth/e-service/services

  • วัตถุประสงค์: บริหารจัดการคำขอรับบริการออนไลน์ตามมาตรฐาน พ.ร.บ.การปฏิบัติราชการทางอิเล็กทรอนิกส์ พ.ศ. 2565
  • ประเภทงานบริการที่รองรับ:
    1. คำร้องทั่วไป (General Petitions)
    2. คำขอลงทะเบียนเบี้ยยังชีพผู้สูงอายุ / คนพิการ (Elderly & Disability Allowances)
    3. คำขอจดทะเบียนพาณิชย์ (Commercial Registrations)
    4. คำขอใบอนุญาตก่อสร้างอาคาร (Construction Permits)
    5. คำขอติดตั้ง / ซ่อมแซมไฟฟ้าสาธารณะ (Electricity Repairs)
    6. คำขอติดตั้งน้ำประปา / ชำระค่าน้ำประปา (Water Services)
    7. คำขอหนังสือรับรองและเอกสารราชการต่างๆ (Certificate Requests)
  • ขั้นตอนการปฏิบัติงานของเจ้าหน้าที่:
    • เจ้าหน้าที่เข้าตรวจสอบรายการคำร้องใหม่ที่ส่งเข้ามา
    • คลิกดูรายละเอียดและตรวจสอบความถูกต้องของเอกสารแนบจากประชาชน
    • อัปเดตสถานะงาน: รอดำเนินการ -> กำลังดำเนินการ -> อนุมัติ / เสร็จสิ้น (หรือ ไม่อนุมัติ)
    • บันทึกข้อความตอบกลับหรือหมายเหตุ เพื่อให้ประชาชนสามารถติดตามสถานะผ่านหน้าเว็บได้

6.2 ศูนย์รับเรื่องร้องทุกข์และเรื่องร้องเรียน (Public Complaints)

  • URL: /auth/e-service/complaints

  • วัตถุประสงค์: รับเรื่องร้องทุกข์ เหตุเดือดร้อนรำคาญ ข้อเสนอแนะ และการแจ้งเบาะแสการทุจริตประพฤติมิชอบ
  • มาตรฐานการคุ้มครองข้อมูลส่วนบุคคล:
    • ระบบแยกช่องทางร้องเรียนทั่วไป และช่องทางร้องเรียนลับ (สายตรงผู้บริหาร / ป.ป.ช. / ป.ป.ท.)
    • ข้อมูลตัวตนของผู้ร้องเรียนจะถูกเข้ารหัสและปกปิดเป็นความลับตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA)

6.3 รายงานสรุปสถิติผลการดำเนินงาน (Service Summary Reports)

  • URL: /auth/e-service/summary

  • วัตถุประสงค์: สรุปภาพรวมและสถิติปริมาณคำร้องแต่ละประเภท รายเดือนและรายปี เพื่อนำไปจัดทำรายงานผลการปฏิบัติงานต่อผู้บริหารและหน่วยงานกำกับดูแล

7. ข้อมูลองค์กรและการประเมินผลมาตรฐาน (Directory & Assessments)

7.1 ระบบความคิดเห็นและแบบสำรวจ (Citizen Feedback & Surveys)

  • ความคิดเห็นประชาชน: /auth/feedback
  • สำรวจความคิดเห็น: /auth/feedback-surveys
ความคิดเห็นและข้อเสนอแนะ แบบสำรวจความพึงพอใจ
  • ความคิดเห็นประชาชน (/auth/feedback): กล่องรับฟังความคิดเห็น การประเมินความพึงพอใจการให้บริการ และข้อเสนอแนะในการพัฒนาองค์กร
  • แบบสำรวจ (/auth/feedback-surveys): สร้างโพลล์และแบบสอบถามออนไลน์เพื่อสำรวจความคิดเห็นของประชาชนในประเด็นสำคัญ

7.2 กระดานสนทนาสาธารณะ (Webboard)

  • URL: /auth/webboard

  • วัตถุประสงค์: ช่องทางการติดต่อสื่อสารและตอบคำถามสาธารณะระหว่างประชาชนและเจ้าหน้าที่
  • การดูแลความเรียบร้อย: เจ้าหน้าที่สามารถตอบกระทู้ ปักหมุดกระทู้สำคัญ หรือลบกระทู้ที่มีข้อความไม่เหมาะสม

7.3 ทำเนียบบุคลากรและโครงสร้างองค์กร (Personnel Directory)

  • URL: /auth/personal

  • วัตถุประสงค์: แสดงผังโครงสร้างผู้บริหาร สมาชิกสภา และข้าราชการ/พนักงานส่วนท้องถิ่น
  • การจัดหมวดหมู่ส่วนราชการ:
    • คณะผู้บริหาร
    • สภาองค์กรปกครองส่วนท้องถิ่น
    • สำนักปลัด
    • กองคลัง
    • กองช่าง
    • กองการศึกษา ศาสนา และวัฒนธรรม
    • กองสาธารณสุขและสิ่งแวดล้อม
  • ข้อมูลบุคลากร: ชื่อ-นามสกุล, ตำแหน่งหน้าที่, ภาพถ่ายประจำตัว, เบอร์โทรศัพท์ติดต่อ และลำดับการแสดงผล

7.4 ระบบประเมินคุณธรรมและความโปร่งใส (ITA) และประสิทธิภาพ (LPA)

  • การประเมิน ITA: /auth/ita
  • การประเมิน LPA: /auth/lpa
การประเมินคุณธรรมและความโปร่งใส (ITA) การประเมินประสิทธิภาพ อปท. (LPA)
  • ระบบ ITA (/auth/ita): จัดการเอกสารและลิงก์เปิดเผยข้อมูลสาธารณะ (Open Data Integrity and Transparency Assessment) ตามเกณฑ์สำนักงาน ป.ป.ช. (ตัวชี้วัด O1 - O43)
  • ระบบ LPA (/auth/lpa): จัดเก็บข้อมูลหลักฐานการประเมินประสิทธิภาพขององค์กรปกครองส่วนท้องถิ่น 5 ด้านหลัก (การบริหารจัดการ, การบริหารงานบุคคล, การบริหารการเงินการคลัง, การบริการสาธารณะ, ธรรมาภิบาล)

8. การบริหารความปลอดภัยและสิทธิ์การเข้าถึง (Security & Administration)

8.1 การจัดการผู้ใช้งานระบบ (User Management)

  • URL: /auth/system-users

  • การสร้างบัญชีใหม่ (Create): กำหนดชื่อผู้ใช้งาน (Username), อีเมล, รหัสผ่านชั่วคราว และมอบหมายบทบาท (Role)
  • การระงับบัญชี (Status): สามารถเปิด/ปิดการเข้าใช้งานระบบของเจ้าหน้าที่แต่ละคนได้ทันทีเมื่อมีการย้ายงานหรือพ้นสภาพ

8.2 บทบาทและสิทธิ์การใช้งาน (Roles & Permissions)

  • บทบาท (Roles): /auth/master/roles
  • สิทธิ์ (Permissions): /auth/master/permissions
การกำหนดบทบาท (Roles) การกำหนดสิทธิ์การเข้าถึง (Permissions)
  • บทบาท (Roles): กำหนดกลุ่มผู้ใช้งานตามหน้าที่ เช่น ผู้ดูแลระบบสูงสุด (Superadmin), เจ้าหน้าที่ประชาสัมพันธ์, เจ้าหน้าที่งานทะเบียน, เจ้าหน้าที่รับเรื่องร้องเรียน
  • สิทธิ์ (Permissions): กำหนดสิทธิ์ระดับละเอียดในแต่ละโมดูลอย่างชัดเจน (เช่น ดูข้อมูลอย่างเดียว, สร้าง/แก้ไขได้, หรือสิทธิ์ในการลบข้อมูล)

8.3 บันทึกประวัติและตรวจสอบการใช้งาน (Audit Logs)

  • URL: /auth/logs

  • วัตถุประสงค์: จัดเก็บหลักฐานการปฏิบัติงานในระบบตาม พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์
  • ข้อมูลที่บันทึก: วันที่และเวลา, ผู้ใช้งาน (Username/ID), กิจกรรมที่กระทำ (สร้าง, แก้ไข, ลบ, ล็อกอิน), โมดูลที่ดำเนินการ และหมายเลข IP Address

9. ข้อแนะนำและมาตรฐานความปลอดภัย (Best Practices)

  1. การบันทึกข้อมูลทุกครั้ง: เมื่อกรอกข้อมูลในฟอร์มเรียบร้อยแล้ว ต้องคลิกปุ่ม "บันทึก" สีเขียวเสมอ หากต้องการยกเลิก ให้คลิกปุ่ม "ยกเลิก" หรือเครื่องหมายกากบาท
  2. การเตรียมขนาดรูปภาพ:
    • ภาพแบนเนอร์หน้าแรก: แนะนำขนาดความละเอียด 1920 x 1080 พิกเซล
    • ภาพปกข่าวสารและกิจกรรม: แนะนำขนาดความละเอียด 800 x 600 พิกเซล (หรือสัดส่วน 4:3)
    • ขนาดไฟล์รูปภาพไม่ควรเกิน 2-5 MB ต่อภาพ เพื่อความรวดเร็วในการเปิดหน้าเว็บของประชาชน
  3. การใช้งานสถานะ "ฉบับร่าง": หากข้อมูลหรือข่าวยังพิมพ์ไม่เสร็จสมบูรณ์ ให้เลือกสถานะเป็น "ฉบับร่าง" ข้อมูลจะถูกบันทึกเก็บไว้เฉพาะในหลังบ้าน และจะไม่ปรากฏต่อสาธารณะจนกว่าจะกดเปลี่ยนเป็น "เผยแพร่"
  4. ความปลอดภัยของบัญชีผู้ใช้:
    • หลีกเลี่ยงการใช้รหัสผ่านที่คาดเดาได้ง่าย เช่น วันเดือนปีเกิด หรือ 123456
    • ควรเปลี่ยนรหัสผ่านเป็นประจำทุก 3 - 6 เดือน
    • ไม่เปิดเผยรหัสผ่าน หรือใช้งานร่วมกันหลายบุคคล
    • ต้องกด "ออกจากระบบ" (Logout) ทุกครั้งหลังเสร็จสิ้นการปฏิบัติงาน โดยเฉพาะเมื่อใช้งานบนเครื่องคอมพิวเตอร์ส่วนกลาง
